# v0.38.2 — 크롬 확장: 로그인하면 패널이 저절로 다시 연결 · 보내기 실패 원인 안내

크롬 웹 스토어가 v0.30.0을 "설명에 적은 기능이 동작하지 않음 — Sign in & send"(Red Potassium)로 반려했습니다. 심사자가 패널에서 로그인하고 질문을 보내는 흐름을 재현하지 못한 것으로 보고, 그 흐름을 다듬었습니다.

## 바뀐 점

- **로그인 뒤 자동 다시 연결** — 패널의 **로그인 탭**을 누르면 그 패널은 10분 동안 "로그인 기다림"이 됩니다. 그동안 새 탭에서 로그인을 마쳐 그 서비스의 쿠키가 바뀌거나, 앱 탭으로 돌아오면 패널이 처음 주소로 저절로 다시 열립니다. 예전처럼 ↻를 직접 누를 필요가 없습니다. 사이드탭도 같습니다.
  - 로그아웃 화면이 열리면서 스스로 심는 쿠키로 계속 다시 열리지 않게, 연 직후 8초의 변화는 무시하고 자동 다시 열기 사이에 10초 간격을 둡니다. 로그인 탭을 누르지 않은 패널은 건드리지 않습니다.
  - background.js는 쿠키 **값**을 보내지 않고 바뀐 **도메인 이름**만 앱 탭 · 사이드탭에 알립니다.
- **이용 동의 화면 안내** — 처음 쓰는 서비스가 이용 동의 화면을 띄우면(지역에 따라 Duck.ai) 패널에 `처음 사용 — 패널 안의 동의 버튼을 눌러 주세요`를 보여 줍니다. 다른 회사의 약관에 사용자 대신 동의하지 않도록 **확장은 버튼을 누르지 않고 읽기만** 합니다. 동의 버튼이 대화 상자 안에 있거나 입력창이 안 보일 때만 동의 화면으로 봅니다.
- **보내기가 조용히 실패하지 않음** — 입력창을 찾지 못했을 때 로그아웃 상태면 `로그인 필요 — 이 패널의 "로그인 탭"을 눌러 …`, 동의 화면이면 `처음 사용 — …`로 알리고, 앱 탭 · 사이드탭 패널 머리줄에 그 상태와 로그인 탭 버튼을 띄웁니다. 다른 패널은 그대로 보냅니다.
- 안내 글(로그인 탭 설명 · 연결 안 됨 · 처음 화면 안내)의 "↻를 누르세요"를 "로그인하면 저절로 다시 연결됩니다"로 바꾸고, 처음 화면 안내에 "Duck.ai는 로그인 없이 됩니다"를 더했습니다.

## 스토어 자료

- `store/README.md` 설명(영어 · 한국어): "이미 로그인된 계정 그대로" → 로그인 탭과 자동 연결, 계정 없이 되는 Duck.ai를 적음.
- 심사자 안내를 **A. 계정 없이 보내기(Duck.ai) → B. 로그인하고 보내기 → C. 사이드탭** 단계로 다시 쓰고, 버튼 이름과 화면에 보이는 글을 적음.
- 4절에 이번 반려 사유와 대응을 적어 둠.

## 알아 둘 점

- 2026-11 한국에서 연 Duck.ai에는 동의 화면이 없었습니다(그대로 보내고 답을 읽는 것까지 확인). 동의 화면 버튼 글은 예전 화면의 `I Agree` · `Get Started` 등을 기준으로 했습니다 — 다른 문구면 `services.js`의 `consent.text`에 더합니다.
- 크롬에서 실제로 로그인 → 자동 다시 연결되는 것은 사람이 확인해야 합니다 — [릴리스 점검표 11-10](../release-checklist.md).
- Windows 앱은 자동 로그인을 쓰므로 이번 변경의 영향이 없습니다(안내 글 사전만 공유).

## 개발

- `services.js`: 서비스 설정 `consent: { text, selectors }`(Duck.ai), `servicesForCookieDomains(domains)` — 쿠키 도메인(상위 · 하위 도메인)을 서비스 id로.
- `page.js`: `pageNeedsConsent(cfg)` — 읽기 전용, 버튼 문구 | false.
- `content.js`: 보내기 결과 code `needs-consent` · `logged-out`, 요청 `mla:consent`. 보내기 설정(`sendCfg`)에 `loggedOut` · `consent`를 실어 보냄.
- `background.js`: 쿠키 변화 300ms 묶음마다 `{ type: 'mla:cookieChanged', domains }`.
- `host-panels.js` · `sidepanel.js`: `armLogin` · `autoReconnect`, 로그인 확인 때 동의 화면도 확인(떠 있는 동안 3초마다 다시 봄). 화면 상태 `needs-consent`.
- 테스트 `test/login-reconnect.test.js`(8개), `lang.test.js`의 페이지 오류 code 목록에 두 개 추가.
