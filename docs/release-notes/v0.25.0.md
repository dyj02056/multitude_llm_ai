고도화 계획(v0.24.0~v0.30.0)의 **2단계** 버전입니다. 쓰는 사람이 보기에 새 기능은 **OS 알림**과 **보내기 전 미리보기**이고, 사이트 셀렉터를 언어와 상관없이 찾게 다듬고 셀렉터를 한 번에 점검하는 개발 도구를 더했습니다.

## 바뀐 점

### OS 알림 (Windows 앱 · 크롬 확장)

- 앱 창(크롬 확장은 앱 탭)을 보고 있지 않을 때 다음 일이 생기면 Windows · 크롬 알림을 띄웁니다.
  - 한 번에 보낸 질문의 답변이 모두 끝남 — 예: `답변 4개 완료`, `답변 3/4개 완료 (시간 초과 1)`
  - 사용 한도에 걸린 것 같음 — 예: `Gemini: 사용 한도에 걸린 것 같습니다`
  - 보내기 실패 — 여러 패널이 거의 동시에 실패하면 서비스 이름을 모아 알림 하나로
  - 종합 · 일치/이견 분석이 끝남(또는 실패)
- 알림에는 **질문 · 답변 글을 넣지 않고** 개수와 서비스 이름만 씁니다.
- 알림을 누르면 앱 창(앱 탭과 그 창)을 앞으로 가져옵니다. 분석이 끝난 알림은 답변 비교 화면을 엽니다.
- **설정(`?`) › 알림**에서 종류마다 끌 수 있습니다 (기본: 모두 켬).
- 크롬 확장은 `notifications` 권한을 더했습니다. **업데이트할 때 크롬이 "알림 표시" 권한을 한 번 묻습니다.** 앱 탭을 닫으면 알림도 오지 않습니다.

### 보내기 전 미리보기

- **보내기**를 Shift+클릭하거나 입력창에서 **Ctrl+Shift+Enter**를 누르면, 보내기 전에 AI마다 실제로 들어갈 것을 보여 줍니다: 최종 글(스킬 지침 + 프로젝트 맥락 + 질문), 직접 올린 첨부, 프로젝트 파일 업로드, 글자 수, 파일 업로드가 실패했을 때 대신 보낼 본문 글자 수.
- 경고: 그 서비스가 받지 않는 파일 종류(빼고 보냄), 서비스 파일 한도보다 큰 파일, 파일 수 초과, 10만 자가 넘는 글.
- **보내기**는 보여 준 그대로 보내고(다시 만들지 않음), **취소**는 보내지 않고 입력 내용 · 첨부를 남깁니다.
- 매번 보려면 **설정(`?`) › 보내기 전 미리보기**를 켭니다 (기본: 꺼짐).
- 미리보기와 실제 보내기가 같은 계산(`src/shared/send-plan.js`)을 씁니다.

### 셀렉터 언어 짝

- 화면 글(aria-label)에 기대는 셀렉터에 한국어 · 영어 짝을 맞췄습니다: Qwen · Z.ai · Genspark의 보내기 · 중지 버튼에 한국어 후보, ChatGPT 보내기에 `프롬프트 보내기` 후보. 모두 기존 후보 **뒤에** 붙여 구조 셀렉터가 먼저 쓰입니다. 지운 후보는 없습니다.
- 서비스 · 항목마다 한국어 셀렉터가 있으면 영어 짝이 있는지(반대도), 로그아웃 문구가 두 언어를 다 찾는지 검사하는 테스트를 더했습니다.

### 개발: `npm run selectors:probe`

- 서비스마다 숨은 창으로 처음 화면을 열어 앱 셀렉터(내장 + 저장소의 `remote/selectors.json`)로 입력창 · 보내기 · 중지 · 답변 · 로그아웃 단서를 찾는지 **읽기만 해서** 점검합니다. 입력 · 클릭 · 보내기를 하지 않습니다.
- `MLA_PROFILE`로 로그인된 앱 프로필을 씁니다(앱을 먼저 끄기). 결과는 터미널 요약과 JSON 보고서, 입력창을 못 찾은 서비스는 `selectors.json`에 넣을 틀(파일은 바꾸지 않음).
- `--fake`는 실제 사이트 대신 가짜 페이지로 도구만 시험합니다(접속 없음). 사용법은 [docs/setup.md](../setup.md#셀렉터-점검-v0250) · [remote/README.md](../../remote/README.md#셀렉터-점검-도구-v0250).

## 확인한 것

- `npm test` 303개 통과 (281개에서 알림 · 보내기 계획 · 셀렉터 언어 짝 · 점검 도구 테스트 22개 추가), `npm run check:ext` 통과.
- 스크린샷 도구로 앱 화면 17개 장면 + 새 장면 `26-send-preview`(미리보기 창)를 띄워 화면 스크립트 오류가 없고(사이드탭 장면의 예전부터 있던 preload 오류만), 설정 화면의 알림 · 미리보기 칸과 미리보기 창 배치를 그림으로 확인했습니다.
- 임시 프로필로 앱을 켜서(모델 고르기 · 채팅 화면) 오류가 없는 것을 확인했습니다.
- `npm run selectors:probe -- --fake`로 정상 · 입력창 못 찾음 · 로그아웃 세 경우의 요약 · JSON 보고서 · 고칠 틀이 나오는 것을 확인했습니다.

## 알아 둘 것

- **실제 알림이 화면에 뜨는 것은 확인하지 못했습니다** (Windows 알림 센터 · 크롬 알림 모두 단위 테스트의 가짜로만 확인). Windows 앱 알림은 설치본(바로가기의 앱 id)에서 뜨고, 개발 실행(`npm start`)에서는 Windows 설정에 따라 안 보일 수 있습니다. 집중 지원(방해 금지)이 켜져 있으면 보이지 않습니다.
- 크롬 확장은 실제 크롬에서 확인하지 않았습니다 (`notifications` 권한 확인 창, 알림 누르기 포함).
- 더한 한국어 셀렉터(`보내기` · `중지`)는 실제 한국어 화면에서 확인하지 않았습니다. 앞쪽 구조 셀렉터를 못 찾을 때만 쓰입니다.
- `selectors:probe`는 실제 사이트에서 돌려 보지 않았습니다(로그인 필요). 보내기 버튼 · 중지 버튼 · 답변은 질문을 보내야 보이는 사이트가 많아 못 찾아도 실패로 세지 않습니다 — 입력창만 기준입니다.
- 미리보기의 "긴 글" 경고 기준(10만 자)은 사이트별 실제 한도가 아니라 프로젝트 모드가 본문으로 넣는 최대 글자 수와 같은 어림값입니다.
