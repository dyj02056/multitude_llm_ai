프로젝트 모드에서 파일 내용을 채팅 본문에 붙여 넣지 않고 **파일 업로드**로 보내도록 바꾼 버전입니다.

## 바뀐 점

- **올리는 방식 선택** — 프로젝트 사이드바 아래 `올리는 방식`에서 고릅니다 (프로젝트마다 저장).
  - **묶음 파일 (기본):** 구조와 파일 내용을 경로가 붙은 `.md` 파일로 묶어 올립니다. 100만 자가 넘으면 `-1.md`, `-2.md`로 나눕니다.
  - **개별 파일:** 파일마다 하나씩 올립니다. 이름에 경로를 넣고(`src/a/index.js` → `src__a__index.js`), 자주 안 받는 형식은 `.txt`를 붙입니다. 본문에 "올린 이름 → 실제 경로" 목록을 넣습니다. 첨부 한도(10개·50MB)를 넘으면 그번만 묶음 파일로 보냅니다.
- **적용 범위:** 첫 질문, 📂 요청 파일 보내기, 전체 파일 다시 요청 모두 같은 방식으로 업로드합니다.
- **업로드를 못 할 때:** 문서 첨부를 받지 않는 서비스(Duck.ai)와 업로드에 실패한 패널에는 같은 내용을 본문에 넣어 보냅니다. 패널에 `📎 업로드 실패 → 본문으로 보냄`이 뜹니다.
- AI가 올린 이름(`src__a__index.js`)으로 `NEED_FILES`를 요청해도 실제 경로로 찾아 줍니다.
- AI의 답변 형식(파일별 diff, `파일: 경로`)은 그대로라 변경 제안·적용·되돌리기는 이전과 같습니다.

## 알아 둘 점

- 서비스에 따라 긴 첨부 문서는 전부 읽지 않고 필요한 부분만 찾아 읽을 수 있습니다. 꼼꼼히 봐야 하는 작은 수정은 파일 수를 줄여 보내면 좋습니다.
- 실제 서비스의 업로드 화면이 바뀌면 업로드가 실패할 수 있습니다. 그때는 자동으로 본문으로 보냅니다.
