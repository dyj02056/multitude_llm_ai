# v0.40.1 — 코드 정리: Windows 앱과 크롬 확장이 같은 설정 규칙을 씀 · 로컬 LLM 패널에도 스킬 지침

화면은 그대로이고, 두 곳에 똑같이 적혀 있던 코드를 한 곳으로 모았습니다. 쓰는 사람이 느낄 변화는 아래 "바뀐 점"의 로컬 LLM 한 가지입니다.

## 바뀐 점

- **Windows 앱: 로컬 LLM 패널에도 스킬 지침 · 프로젝트 본문이 붙음** — 보내기 옵션을 검사할 때 웹 서비스 패널 몫만 남기고 로컬 LLM 패널 몫(스킬 지침 `prefixById` · 프로젝트 본문 `textById` · `plainIds`)은 버리고 있었습니다. 이제 켜 둔 로컬 LLM 패널 몫도 남깁니다. 크롬 확장은 원래 붙이고 있었습니다.
- **크롬 확장: 보내기 옵션을 Windows 앱과 같은 규칙으로 검사** — 지금까지 확장은 프로젝트 이름만 다듬고 나머지는 그대로 넘겼습니다. 이제 아는 항목만 받고 길이를 자릅니다(질문 2만 자 · 예비 글 20만 자 · 스킬 지침 2만 5천 자). 이어서 보내기(`sendFollowUp`)도 같은 검사를 거칩니다. 화면은 두 쪽이 같아서 지금 보내는 값이 막히지는 않습니다.

## 개발

- 새 공통 모듈 `src/shared/prefs.js`(Windows 앱 `require` · 확장 `MLA.prefs`)
  - `normalizePrefs(prefs, saved)` — 저장된 설정을 지금 서비스 목록 · 값 범위에 맞춤(없어진 서비스, 로컬 패널 다시 넣기, 배치 · 종합 담당 · 기록 개수 · 알림 · 추천 · 언어 · 첫 사용 안내). `main.js loadPrefs`와 `host.js init`에 두 번 있던 코드.
  - `cleanSendOpts(opts, ids)` — 보내기 옵션 검사. `main.js sendOpts`와 `host.js cleanSendOpts`를 하나로, 패널 id는 양쪽 다 `allServices()`.
- `local-llm.js`: `mergeLocalPrefs(cur, next)` — 설정 화면에서 바꾼 로컬 LLM 값을 합침(주소가 이 PC가 아니면 `null`). `ipc/settings.js`와 `host.js`의 같은 코드를 대신함. 확장의 권한 요청은 그대로 확장 쪽에.
- 다른 파일에서 쓰지 않는 export 8개를 뺌(`clearTransfer` · `projectCall` · `SAVE_KINDS` · `okTagInput` · `TMP_MARK` · `MAX_PATHS` · `MAX_MESSAGE` · `SUBCOMMANDS`) — 함수는 그대로.
- `build-extension.js`의 `APP_SHARED`에 `prefs`.
- 테스트 `test/prefs.test.js`(5개). 예전 코드 줄을 직접 찾던 연결 테스트 7곳을 새 위치로 옮김.

## 알아 둘 점

- 실제 로컬 LLM 서버(Ollama 등)에 스킬을 붙여 보내는 것과, 크롬에 올린 확장 탭에서 설정을 불러오는 것은 사람이 확인해야 합니다 — 자동 테스트 · 스크린샷은 가짜 본체로 돕니다.
