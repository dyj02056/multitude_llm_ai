원격 셀렉터 **서명 검사를 켰습니다**. v0.23.0에서 만든 검사 기능에 실제 공개 키를 넣은 버전입니다.

## 바뀐 점

- Windows 앱과 크롬 확장에 Ed25519 공개 키(`PzJTDLNFvJg3IZjz3cWMXtxPzeklRUcc8TOsfNBsXGI=`)가 들어 있습니다.
- GitHub의 `remote/selectors.json`을 받으면 함께 받은 `remote/selectors.json.sig`로 **받은 바이트 그대로** 서명을 확인하고, 맞을 때만 적용합니다.
  - 맞지 않거나 `.sig`를 받지 못하면 적용하지 않고, 마지막으로 검사를 통과한 캐시(없으면 앱에 든 내장 값)를 씁니다. 설정(`?`)의 셀렉터 상태에 `확인 실패: 서명 확인 실패`로 나옵니다.
  - 앱을 켤 때 저장해 둔 캐시도 다시 확인합니다. v0.23.0 이전이 남긴 서명 없는 캐시는 버리고 새로 받습니다.
- 셀렉터를 고칠 때는 `npm run selectors:sign`으로 다시 서명해 `selectors.json`과 `.sig`를 같이 커밋해야 합니다. 서명을 잊으면 테스트(`test/remote-sign.test.js`)가 실패해 CI에서 알 수 있습니다.

## 확인한 것

- `npm test` 259개 통과 (저장소의 `selectors.json`과 `.sig`가 앱의 공개 키로 맞는지 보는 테스트 추가), `npm run check:ext` 통과.
- GitHub에서 받은 `selectors.json` 바이트로 Node(Windows 앱 경로)와 Chromium 156 WebCrypto(크롬 확장 경로) 모두에서 서명이 맞고, 한 바이트만 바꿔도 실패하는 것을 확인했습니다.

## 알아 둘 것

- 크롬 137보다 오래된 크롬에서는 WebCrypto에 Ed25519가 없어, 확장은 원격 셀렉터를 적용하지 않고 내장 · 캐시 값을 씁니다.
- 예전에 서명된 `selectors.json`을 다시 내보내는 것(되돌리기 공격)까지는 막지 못합니다.
