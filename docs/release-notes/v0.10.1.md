안정성과 보안을 다듬은 버전입니다. 화면과 기능은 그대로입니다.

## 바뀐 점

- **로그인 팝업을 더 엄격하게** (Windows 앱) — 예전에는 주소에 `login`·`oauth` 같은 글자만 있어도 앱 안 팝업으로 열었습니다. 이제는 주소의 도메인이 허용 목록과 **정확히 같을 때만** 앱 안에서 엽니다.
  - 허용 목록: 공용 로그인 도메인(`accounts.google.com` · `appleid.apple.com` · `login.microsoftonline.com` · `login.live.com` · `github.com` · `x.com` 등) + 그 서비스의 로그인 도메인(예: ChatGPT의 `auth.openai.com`) + 서비스 자기 도메인
  - `evil.com/login`, `x.com.evil.com`, `accounts.google.com.evil.com`, `http://` 주소는 앱 안에서 열지 않고 기본 브라우저로 엽니다.
  - 팝업 안에서 다른 곳으로 이동하거나 리다이렉트될 때도 같은 검사를 합니다. 허용 밖이면 막고 기본 브라우저로 엽니다.
- **크롬 확장: 이름이 같은 프로젝트 폴더** — 폴더를 처음 열 때 고유 id를 만들어 폴더와 함께 기억합니다. 같은 폴더인지는 크롬의 `isSameEntry()`로 확인하므로, `C:\work\app`과 `D:\other\app`처럼 이름이 같은 두 폴더의 고른 파일 · 규칙 · 적용 기록이 섞이지 않습니다. 같은 폴더를 다시 열면 지난 상태가 이어집니다.
  - 예전 버전에서 프로젝트 상태(고른 파일 등)가 확장 저장소에 제대로 저장되지 않던 문제도 함께 고쳤습니다. 예전 방식으로 저장된 폴더 기억과 상태는 자동으로 옮깁니다.
- **프로젝트 업로드: 바이트 기준으로 나누기** — 묶음 파일(`project-context.md` 등)을 글자 수(100만 자)가 아니라 **UTF-8 바이트(100만 바이트)** 로 나눕니다. 한글은 한 글자가 3바이트라, 예전에는 한글 문서가 많으면 묶음 파일 하나가 2~3MB가 될 수 있었습니다.
  - 파일 하나가 한도보다 크면 그 파일도 `1/2`, `2/2` 조각으로 나눕니다 (조각마다 코드 블록이 닫힙니다).
  - 서비스마다 파일 하나의 한도를 둘 수 있게 했고(`upload.maxFileBytes`, 지금은 모두 공통 한도 25MB), 묶음 파일도 보낼 서비스 중 가장 작은 한도 안으로 나눕니다.
- **창 크기를 끌 때 덜 버벅임** (Windows 앱) — 창 크기를 바꾸는 동안 패널 배치와 화면 상태 전송을 약 30ms씩 묶어서 합니다 (끄는 동안 100번 → 2~3번).
- **작은 정리**
  - 첨부: 파일을 패널에 옮기다 오류가 나도 페이지에 옮겨 둔 조각을 항상 지웁니다.
  - 사이트 셀렉터 원격 갱신: 리다이렉트를 따라가지 않습니다 (Windows 앱 · 크롬 확장). 실패하면 지금 값을 그대로 씁니다.
  - 프로젝트 파일 쓰기 · 지우기 (Windows 앱): 바로 직전에 상위 폴더의 실제 위치를 다시 확인하고, 대상이 바로가기(링크)면 거절합니다.

## 업데이트

- Windows 앱: 새 설치 파일로 덮어 설치하면 로그인 · 설정 · 기록이 그대로 남습니다.
- 크롬 확장: `chrome://extensions`에서 ↻(새로고침)을 누릅니다. 프로젝트를 열어 둔 상태였다면 앱 탭에서 **폴더 접근 허용**을 한 번 눌러 주세요.
