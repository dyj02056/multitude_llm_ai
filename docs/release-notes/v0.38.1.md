# v0.38.1 — 로드맵 고침 (대시보드가 Windows 앱에서 깨지던 문제 · 설정 · 그림 가독성)

v0.38.0 로드맵 기능을 검토하고 고쳤습니다. 사용법은 [로드맵 안내](../roadmap.md).

## 고친 점

- **Windows 앱에서 대시보드 그림이 깨지던 문제** — 그림 색 · 크기 CSS를 `<style>`로 끼워 넣었는데 앱의 보안 정책(CSP `style-src 'self'`)이 막아, 링이 화면을 덮을 만큼 커지고 색이 모두 빠졌습니다(작업 칸의 상태 색 줄도). 같은 CSS를 `styles.css`에 두고, 두 곳이 같은지 테스트가 검사합니다. 크롬 확장은 영향이 없었습니다.
- **계획을 나누기 전에 바꾼 설정이 무시되던 문제** — 로드맵이 없을 때 문서 탭에서 "문서 자동 생성"을 꺼도 분해하자마자 문서를 썼습니다. 이제 그 설정을 새 로드맵에 넘깁니다. (이 동작을 정상으로 굳혀 두었던 테스트 단언도 바로잡음)
- **README "끝에 붙이기"** 모드에서 소개 구역 위에 `## intro`라는 키 이름 제목이 붙던 문제.
- **문서 쓰기가 중간에 실패하면** 덮어쓴 파일만 되돌리고 새로 만든 파일은 남던 문제 — 이제 새 파일도 지웁니다.
- **완료한 작업을 되돌리면** 그 작업 뒤에 이어지는 작업 중 이미 시작 · 완료한 것을 알려 줍니다(후속 작업의 상태는 그대로).
- **소개 문장 가져오기**가 계획 탭에서 고른 AI의 답을 먼저 씁니다(전에는 처음 읽힌 아무 패널의 답).
- **AI에게 분해 부탁 · 소개 문장 받기**를 두 번 눌러도 한 번만 보냅니다.

## 그림 · 화면

- 긴 한글 제목이 막대 왼쪽에서 잘리거나 지도의 옆 열과 겹치던 문제 — 글자 수가 아니라 대략의 폭으로 줄여 `…`을 붙입니다.
- 같은 마일스톤 안의 선행 화살표가 칸 뒤로 숨던 문제 — 칸 왼쪽 여백으로 돌아 들어갑니다.
- **진행 링**: 칠한 부분의 합이 가운데 %와 같도록(상태마다 진행률에 보탠 몫만큼) 그립니다. 전에는 막힘 · 대기까지 색으로 칠해 숫자와 맞지 않았습니다.
- 막대 위 기호: HTML 내보내기(흰 바탕)에서 대기 ○가 보이지 않던 문제, 노랑(진행 중) 위 흰 기호의 낮은 대비를 고침.
- **번다운**: 마감일 없이 그리던 "이상선"을 빼고, 시작부터 지금까지의 평균 속도로 0에 닿는 예상선만 그립니다.
- 작업 탭의 상태 고르기 칸이 어두운 화면에서 흰 바탕으로 뜨던 것, 작업 칸 아래 빈 여백을 고침.
