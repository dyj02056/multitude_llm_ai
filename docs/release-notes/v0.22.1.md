Windows 앱의 **기록 · 설정 · 라이브러리 · 프로젝트 상태를 암호화해 저장**합니다.

## 바뀐 점

- **암호화하는 파일**: 앱 데이터 폴더의 `history.json`(질문 · 답변 기록) · `prefs.json`(설정) · `library.json`(템플릿 · 스킬) · `projects/*.json`(프로젝트 상태, 되돌리기용 원본 포함) · `devtest-recovery.json`(테스트 실행 중 원본).
- **방식**: Electron `safeStorage`(Windows DPAPI)를 씁니다. 열쇠는 이 Windows 계정에 묶여 있습니다.
  - 막는 것: 파일만 복사해 가는 것, 다른 Windows 계정, 다른 PC.
  - 막지 못하는 것: 같은 계정에서 도는 프로그램(악성 프로그램 포함).
- **업데이트할 때**: 예전 평문 파일은 처음 읽을 때 그대로 읽고, 곧바로 암호화해 다시 씁니다. 평문 사본은 남기지 않습니다.
- **안전하게 쓰기**: 임시 파일에 쓴 뒤 이름을 바꿔, 쓰는 도중 앱이 꺼져도 원래 파일이 깨지지 않습니다.
- **풀 수 없는 파일**(다른 PC · 다른 계정에서 복사해 온 것 등)은 지우지 않고 `<이름>.unreadable-<시각>`으로 옮긴 뒤, 빈 상태로 시작합니다.
- 암호화를 쓸 수 없는 환경이면 예전처럼 평문으로 저장하고, 설정(`?`) › **저장**에 그렇게 표시합니다.
- **크롬 확장은 그대로**(암호화 없음)입니다. 확장에는 OS 열쇠 보관소가 없어 암호화해도 열쇠를 데이터 옆에 둘 수밖에 없습니다. 이 이유를 설정 화면과 [보안](../security.md) 문서에 적었습니다.

## 확인한 것

- `npm test` 175개 통과. 가짜 safeStorage로 다음을 시험합니다.
  - 저장한 파일이 암호문이고 평문 글이 없는지, 다시 읽으면 같은지
  - 예전 평문 파일을 암호화로 바꾸는지
  - 못 푸는 파일을 옆으로 옮기는지
  - 깨진 파일 · 없는 파일 · 암호화를 못 쓰는 환경
  - 본체가 다섯 파일 모두 이 저장소로 쓰는지
- 실제 Electron(Windows DPAPI)으로 확인했습니다: 평문 → 암호문 바꾸기, 파일에 평문 없음, 다시 읽기.
- 임시 프로필로 앱을 켜 시작 오류가 없는 것을 확인했습니다.
