긴 코드를 고칠 때 AI의 출력 한도로 답이 끊겨 **수정이 끝까지 안 되던 문제**를 두 가지로 고쳤습니다.

## 1. 잘린 답변 막기

예전에는 답이 중간에 끊긴 파일도 "전체 내용"으로 받아들여, 적용하면 끊긴 곳 뒤의 코드가 **모두 지워질 수 있었습니다.** 이제는:

- **코드 블록이 닫히지 않은 수정안**(로컬 LLM, 찾기/바꾸기의 끝 표시가 없는 경우 등)은 **적용 불가**로 막습니다. 변경 바에 `✂ 답변이 잘림 N개`가 뜨고, 변경 제안에서 **다시 요청**할 수 있습니다.
- 웹 채팅은 잘린 답도 코드 상자를 닫아서 보여 주므로, 다음 경우를 **의심**으로 표시합니다:
  - 코드 파일인데 괄호가 닫히지 않았을 때 (원본보다 더 많이)
  - 전체 교체인데 원본의 끝부분이 통째로 사라졌을 때
  - `// ... 기존 코드 ...`, `# ... (생략)`, `<!-- 이하 동일 -->`처럼 코드를 줄인 표시가 있을 때
- 의심인 파일은 바의 **적용 (N)**에서 빠지고(`⚠ N개 확인 필요`), 미리보기에서 기본으로 체크되지 않으며 이유가 함께 보입니다.
- 📋 모아보기에서도 잘린 파일을 알려 줍니다.

## 2. 바꿀 곳만 받기 (찾기/바꾸기)

- 답변 규칙을 바꿨습니다: 새 파일이나 150줄 이하 파일은 지금처럼 **전체 내용**, **150줄보다 긴 기존 파일은 바꿀 곳만** 같은 코드 블록 안에 `<<<<<<< 찾기` / (지금 내용 그대로) / `=======` / (바꾼 내용) / `>>>>>>> 바꾸기`로 받습니다. 한 블록에 여러 번 써도 됩니다. 긴 파일 수정의 출력량이 크게 줄어 답이 잘리지 않습니다.
- 앱은 찾을 부분이 지금 파일에 **딱 한 곳** 있을 때만 바꿉니다 (줄 끝 · 앞뒤 공백 차이는 너그럽게). 못 찾거나 여러 곳이면 적용하지 않고 이유를 보여 줍니다. 영어 표시(`SEARCH` / `REPLACE`)도 받습니다.
- 미리보기 · 덩어리 고르기 · 테스트 실행 · 되돌리기는 지금처럼 동작합니다.
- **다시 요청**(예전 "전체 파일 다시 요청"): 지금 내용을 첨부해 다시 달라고 하고, 긴 파일은 찾기/바꾸기로, 잘린 답이었으면 "답이 잘려서"라고 알려 줍니다.
- 코드 리뷰 템플릿과 "종합으로 합치기"에도 같은 규칙을 넣었습니다. "코드 수정 (파일 모아보기)" 템플릿은 그대로 붙여 넣을 전체 파일을 받는 용도라 바꾸지 않았습니다.
