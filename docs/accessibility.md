# 접근성

[← README](../README.md)

v0.30.0에서 앱 화면(`src/renderer/index.html`)과 크롬 사이드탭(`extension/sidepanel.html`)을 **WCAG 2.1 AA**를 기준으로 훑어보고 고친 것, 그리고 아직 모자란 것을 적습니다.
자동으로 검사할 수 있는 것은 `npm test`(`test/a11y.test.js`)에 넣었고, 사람이 직접 써 봐야 아는 것은 [출시 전 확인 목록](release-checklist.md)의 "키보드만으로 한 바퀴"에 있습니다.

> 이 문서의 확인은 **코드 · 화면 뼈대 검사와 계산**으로 한 것입니다. 실제 화면 읽기 프로그램(NVDA · 내레이터)으로는 확인하지 않았습니다.

## 확인하고 고친 것

### 색 대비 (글자)

화면의 색은 `src/renderer/styles.css` 맨 위 `:root`의 이름표로 정합니다. 글자색 이름표마다 세 바탕색(`--bg` #0d1117 · `--bg-2` #161b22 · `--field-hover` #1c2128)과의 대비를 계산했습니다 (보통 글자는 **4.5:1** 이상이 AA).

| 글자색 | 쓰는 곳 | #0d1117 | #161b22 | #1c2128 |
|---|---|---|---|---|
| `--text` #c9d1d9 | 본문 | 12.3 | 11.2 | 10.5 |
| `--text-2` #8b949e | 설명 글 | 6.2 | 5.6 | 5.3 |
| `--muted` **#848d97** | 아주 흐린 보조 글 · 입력칸 안내 글 | 5.6 | 5.1 | 4.8 |
| `--accent` #58a6ff · `--accent-text` #79c0ff | 강조 | 7.5 · 9.7 | 6.9 · 8.9 | 6.4 · 8.3 |
| `--ok` · `--warn` · `--err` | 상태 | 7.5 · 7.5 · 5.7 | 6.8 · 6.9 · 5.2 | 6.4 · 6.4 · 4.8 |

- **고친 것**: `--muted`가 #6e7681(대비 4.1 · 3.8 · 3.5)이라 기준에 못 미쳐 **#848d97**로 밝혔습니다. 이 색을 쓰는 곳(약 60곳: 보조 설명, 입력칸 안내 글, 시간 · 글자 수 등)이 모두 함께 바뀝니다.
- 채운 단추(`.primary`)는 밝은 바탕(`--text`)에 어두운 글자(`--bg`)로 12.3:1입니다.
- 테스트가 이 표의 조합을 다시 계산해, 나중에 색을 바꾸다 4.5 아래로 내려가면 실패합니다.

### 키보드 포커스가 보이는가

- 버튼 · 체크 상자 · 접는 줄(`summary`) · 링크 · Tab으로 닿는 줄에 **2px 파란 테두리**(`:focus-visible`, 마우스로 누를 때는 생기지 않음).
- 입력칸 · 고르기 칸은 테두리 색이 파랑으로 바뀝니다. 공통 입력창(`#prompt`) · 사이드탭 입력창 · 파일 편집기는 예전에는 포커스 표시가 거의 안 보여서 파란 테두리 / 안쪽 선을 더했습니다.
- `outline: none`을 쓰는 규칙은 모두 대신 보이는 표시가 있는지 테스트가 봅니다.

### 키보드로 모든 동작에 닿는가

- 버튼이 아닌데 누를 수 있던 것에 `tabindex`와 Enter · Space를 달았습니다: 라이브러리 목록의 줄(템플릿 · 스킬 · 프리셋), 프로젝트 파일 나무의 줄(v0.31.0부터 방향키로 움직이는 `tree`), 분석 표의 **AI 입장 칸**(그 답변의 관련 문단으로 가기). 기록 목록의 줄은 원래부터 됐습니다.
- 파일 나무의 ▸ 표시는 이름과 같은 일을 해서 화면 읽기 프로그램에는 숨겼고(`aria-hidden`), 체크 상자에는 파일 경로를 이름으로 달았습니다.
- 그 밖의 동작은 원래 `<button>` · `<select>` · `<input>`이라 Tab으로 닿습니다. 앱 전체 단축키는 [사용 안내 › 단축키](guide.md#단축키).

### 창 (dialog)

미리보기 · 적용, 화면 상태(자가진단), 보내기 전 미리보기, 토론, 설정 가져오기 — 다섯 창 모두:

- `role="dialog"` · `aria-modal="true"` · 제목으로 이름표(`aria-labelledby`). (미리보기 · 적용, 화면 상태 창에는 빠져 있어서 더했습니다.)
- 열리면 포커스가 창 안으로 들어가고, **Tab이 창 안에서만 돌며**, 닫히면 열기 전에 있던 버튼으로 돌아옵니다 (`src/renderer/a11y.js` — 창마다 따로 고치지 않고 `hidden` 속성 변화를 지켜봅니다).
- **Esc**로 닫힙니다 (원래부터: 본체 단축키가 "패널 화면으로"로 처리).

### 이름표

- 화면 뼈대의 버튼 · 입력칸 · 고르기 칸 약 200개에 모두 이름이 있는지 테스트가 봅니다: 보이는 글, `<label>`, `aria-label`(사전 키 `data-i18n-aria`), 또는 설명(`title`).
- **기호만 있는 버튼**(`?` `⟳` `⟨` `✕` `↻`, 패널 머리줄의 `→ ⤢ + ← ⌂ ↻ { }` 등)은 설명 글을 `aria-label`로도 달았습니다. 스크립트가 만드는 버튼은 만드는 도우미(`button()` · `tbutton()`)가 자동으로 답니다.
- 이름이 없던 입력칸에 이름을 달았습니다: 공통 입력창, 기록 검색, git 명령 칸, 파일 편집기, 압축본 칸, 사이드탭 입력창.
- 언어를 바꾸면 이름표도 그 언어로 바뀌고, 문서의 `lang` 속성도 맞춥니다.

### 바뀌는 글 읽어 주기

- 입력창 아래 안내(`#sendHint` — 보낸 결과 · 종합 진행), 툴바의 준비 상태, 각 창의 상태 줄, 설정 옮기기 결과, 사이드탭 안내에 `role="status"` · `aria-live="polite"`.

### 표

- 응답 통계 · 서비스 화면 상태 · 자가진단 · 섞어서 적용 · 추천 · 분석 표는 머리줄(`<th>`)이 있습니다. 단축키 표에는 보이지 않는 머리줄(단축키 / 하는 일)을 더했습니다.

### 움직임

- 시스템에서 "움직임 줄이기"를 켜 두면(`prefers-reduced-motion`) 깜빡임 · 전환 효과를 끕니다.

## 알려진 모자란 점

- **AI 사이트 화면 자체**(패널 안의 Gemini · ChatGPT 등)는 그 사이트의 것이라 이 앱이 고칠 수 없습니다. 패널 안으로 Tab이 들어가면 그 사이트의 순서를 따릅니다. 패널에서 앱으로 돌아올 때는 `Ctrl+L`(공통 입력창).
- **선 · 테두리 대비 (v0.31.0에서 고침)**: 버튼 · 입력칸 · 고르기 칸의 테두리는 v0.30.0까지 `--border` #30363d로 바탕과 1.6:1이라 글자가 아닌 요소의 기준(3:1, WCAG 1.4.11)에 못 미쳤습니다. 이제 `--control-border` #656d76(세 바탕에서 3.1~3.6:1)을 씁니다. 칸을 나누는 선 · 상자 테두리 · 꾸밈 선은 요소를 알아보는 데 필요하지 않아 옅은 `--border` 그대로입니다.
- **패널 머리줄의 상태 글**(답변 중… 3 s 등)은 1초마다 바뀌어 읽어 주기(`aria-live`)를 달지 않았습니다. 대신 툴바의 준비 상태(n/n ready)와 입력창 아래 안내가 읽힙니다.
- **색만으로 구분하는 곳**: 패널 머리줄의 상태 점(초록 · 노랑 · 빨강)은 옆에 상태 글이 함께 나오지만, 서비스를 구분하는 색 띠는 이름과 함께여서 색만은 아닙니다. 차이 강조(답변 비교)의 배경색은 색에 기대는 편입니다.
- **파일 나무 (v0.31.0에서 고침)**: `role="tree"` · 줄은 `treeitem`(`aria-level` · `aria-expanded` · `aria-checked`)이고, Tab 한 번으로 닿아 방향키로 움직이며, 다시 그려도 보던 줄에 포커스가 남습니다. 키 설명은 [단축키](guide.md#단축키). 모자란 점: 아주 큰 폴더(수천 줄)는 줄마다 요소를 만들어 화면 읽기 프로그램이 느릴 수 있고, 줄 안의 체크 상자는 Tab이 아니라 Space로만 누릅니다.
- **분석 표의 누르는 칸**은 표의 칸(`<td>`)인 채로 Tab · Enter만 받습니다 (버튼 역할을 주면 표 구조가 깨져서). 설명(title)으로 무엇을 하는지 알립니다.
- **꺼진 단추**는 흐리게(불투명도 0.45~0.5) 보입니다 — 꺼진 요소는 대비 기준의 예외입니다.
- **확대 (v0.31.0에서 고침)**: 글꼴이 12.5px 고정폭이라 작습니다. Windows 앱은 메뉴를 없앴어서 기본 확대 키가 듣지 않았는데, 이제 `Ctrl` `+` / `-` / `0`을 직접 받아 앱 화면(툴바 · 입력창 · 목록 · 창)을 80%~200%(8단계)로 바꾸고 기억합니다. AI 사이트 패널은 그 사이트의 크기 그대로입니다. 크롬 확장은 브라우저 확대가 됩니다. 모자란 점: 200%에서 창이 좁으면 패널 칸이 아주 작아지고(최소 폭 960px은 그대로), 400% 확대 · 좁은 폭의 배치는 확인하지 않았습니다.
- **화면 읽기 프로그램으로 실제 확인은 하지 않았습니다.** 창을 열 때 제목을 읽는지, 목록 줄의 역할이 자연스러운지는 직접 들어 봐야 합니다.
- 확인 · 알림은 브라우저 기본 창(`confirm` · `alert`)을 씁니다 (접근성은 좋지만 모양을 바꿀 수 없음).

## 고칠 때 지킬 것

- 새 버튼은 `<button>`으로. 기호만 넣을 때는 `data-i18n-aria`(뼈대) 또는 `tbutton()` · 설명이 있는 `button()`(스크립트)을 씁니다.
- 새 입력칸에는 `<label for>` 또는 `data-i18n-aria`.
- 새 창은 `<div class="modal" hidden><div class="modal-box" role="dialog" aria-modal="true" aria-labelledby="…">` 모양으로 — 포커스 관리는 저절로 붙습니다.
- 새 글자색은 `:root` 이름표로 만들고 `test/a11y.test.js`의 목록에 더합니다.
