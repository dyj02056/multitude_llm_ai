# 출시 전 확인 목록

[← README](../README.md) · [설치 · 빌드 · 개발](setup.md)

새 버전을 올리기(태그를 푸시하기) 전에 **사람이 직접** 해 보는 확인입니다. 자동 테스트와 스크린샷 도구는 가짜 본체 · 가짜 크롬 API · 테스트용 채팅 페이지로 돌기 때문에, 아래 항목은 그것만으로는 알 수 없습니다.
릴리스 노트의 "알아 둘 것"에는 여기서 **하지 못한 항목**을 그대로 적습니다.

표시: ☐ 아직 · ☑ 확인 · ✗ 문제 있음(릴리스 노트에 적기)

## 0. 자동 확인 (먼저)

```powershell
npm test                 # 단위 테스트 전부 통과
npm run check:ext        # extension/ 이 src/와 맞는지
$env:MLA_SHOT_OUT = "$env:TEMP\mla-shots-ko"; npm run screenshots           # 한국어 장면 (콘솔 오류가 없어야 함)
$env:MLA_SHOT_LANG = "en"; $env:MLA_SHOT_OUT = "$env:TEMP\mla-shots-en"; npm run screenshots   # 영어 장면
Remove-Item Env:MLA_SHOT_LANG, Env:MLA_SHOT_OUT
```

- ☐ `npm test` 실패 0개, `npm run check:ext` 통과
- ☐ 스크린샷 두 번 모두 `console error` 줄이 없음
- ☐ 그림을 열어 본다: 한국어는 지난 버전과 같은 모양인지, 영어는 **한국어가 남은 곳 · 키 이름(`ui.x.y`)이 그대로 보이는 곳 · 넘치거나 줄이 바뀐 버튼**이 없는지 (적어도 01 · 02 · 04 · 05 · 06 · 12 · 13 · 17 · 24 · 26 · 28 · 32 · 37 · 42 · 45). 예시 질문 · 답변 · 일부 가짜 화면(11 · 24의 상태 글)은 한국어가 맞습니다.
- ☐ 화면이 바뀐 장면은 `npm run screenshots`로 `docs/screenshots`를 다시 만들었는지
- ☐ `package.json` · `package-lock.json`(맨 위와 `packages[""]`) · README 배지 · `extension/manifest.json`(build:ext가 맞춤)의 버전이 같은지

## 1. Windows 앱 — 로그인 (실제 계정)

개발 실행은 쓰는 프로필과 섞이지 않게 따로 띄웁니다: `$env:MLA_PROFILE = "$env:TEMP\mla-check"; npm start`

- ☐ 처음 켜면 Google 로그인 화면 → 로그인 → 모델 고르기 화면으로 넘어감
- ☐ 모델을 열면 각 패널이 "Google로 계속하기"로 로그인됨. **Google 계정 고르기 팝업**이 뜨는 서비스(ChatGPT · Claude · Perplexity 등)에서 팝업이 열리고 닫힌 뒤 패널이 로그인 상태가 됨
- ☐ **Apple로 로그인** 팝업을 쓰는 서비스 하나에서 팝업이 열림 (계정이 없으면 창이 뜨는 것까지만)
- ☐ 캡차 · 2단계 인증이 뜨면 패널 머리줄에 안내가 보이고, 직접 풀면 이어짐
- ☐ 로그아웃 → 다시 로그인 화면

## 2. Windows 앱 — 기본 흐름 (실제 사이트)

- ☐ 질문 하나를 4개 패널에 보내 모두 답이 오고, 머리줄이 "답변 완료 · n자"가 됨
- ☐ 파일 첨부(그림 1 · 문서 1)가 받는 서비스에 올라감
- ☐ 종합 요청 → 답변 비교 › 분석 탭에 표가 나옴. 토론 1라운드
- ☐ 기록에 남고, MD · HTML 저장이 됨
- ☐ 프로젝트 폴더 열기 → 수정안 → 미리보기 → 적용 → 되돌리기 (작은 연습 폴더로)

## 3. 셀렉터 점검 (로그인된 프로필)

**앱을 먼저 끕니다** (같은 프로필을 두 프로그램이 함께 열 수 없습니다).

```powershell
$env:MLA_PROFILE = "$env:APPDATA\Multitude LLM"; npm run selectors:probe
Remove-Item Env:MLA_PROFILE
```

- ☐ 로그인해 둔 서비스마다 입력창 `ok`. `입력창 못 찾음`이 있으면 [remote/README.md](../remote/README.md)대로 셀렉터를 고치고 서명
- ☐ 한국어 · 영어 화면 둘 다에서 보내기 버튼을 찾는지 (사이트 언어를 바꿔 한 서비스만이라도)

## 4. OS 알림 (설치한 빌드에서)

개발 실행에서는 Windows가 앱 이름을 몰라 알림이 안 보일 수 있습니다. `scripts\build-win.ps1`로 만든 설치 파일을 깔아 확인합니다.

- ☐ 질문을 보내고 **다른 창으로 가 있으면** 답변 완료 알림이 화면에 뜸. 누르면 앱이 앞으로 옴
- ☐ 앱을 보고 있을 때는 뜨지 않음
- ☐ 설정에서 종류를 끄면 그 종류는 뜨지 않음
- ☐ 알림 글이 설정한 언어로 나옴

## 5. 자동 업데이트 (이전 버전에서)

- ☐ 바로 전 버전 설치 파일을 깐 뒤, 새 버전을 **draft가 아닌 릴리스**로 올리고(또는 시험 저장소에) 앱을 켜 30초 뒤 툴바에 `update x.y.z`가 뜸
- ☐ 설정 › 업데이트 › **다운로드** → **다시 시작해서 설치** → 새 버전으로 켜짐 (설정 화면 아래 버전 확인)
- ☐ 업데이트 뒤에도 로그인 · 기록 · 설정 · 라이브러리가 그대로임

## 6. 예전 데이터 옮기기 (v0.23.x → 지금)

v0.24.0에서 기록 저장 모양이 `history.json` 하나에서 `history/index.json` + 기록별 파일로 바뀌었습니다.

- ☐ v0.23.x로 기록을 몇 개 만든 프로필(또는 보관해 둔 `%APPDATA%\Multitude LLM` 사본)을 `MLA_PROFILE`로 지정해 새 버전을 켬 → 기록 화면에 예전 기록이 모두 보임
- ☐ 프로필 폴더에 `history\` 폴더가 생기고 예전 `history.json`은 없어짐 (개수가 같을 때만 지움)
- ☐ 응답 통계 · 태그 · 검색이 예전 기록에도 동작
- ☐ 크롬 확장도 같은 확인: 예전 버전에서 쓰던 크롬 프로필에서 확장을 새 버전으로 ↻ → 기록이 보임

## 7. 크롬 확장 (실제 크롬)

1. `chrome://extensions` → 개발자 모드 → **압축해제된 확장 프로그램을 로드합니다** → 저장소의 `extension` 폴더 (이미 있으면 ↻)
2. 오류 버튼이 생기지 않는지 봅니다 (서비스 워커 · 매니페스트 오류).

- ☐ 아이콘을 누르면 앱 탭이 열리고, 고른 모델이 iframe으로 뜸 (회색 "연결 거부" 화면이 아님)
- ☐ 질문 보내기 · 답변 감지 · 종합
- ☐ **권한 창**: 설치할 때 묻는 권한이 [store/README.md](../store/README.md)의 설명과 같음. **알림** 권한 — 답변 완료 알림이 뜸
- ☐ **오른쪽 클릭 메뉴**: 글을 선택해 "선택한 글로 묻기", 빈 곳에서 "이 페이지로 묻기" · "사이드탭에서 이 페이지 묻기". 메뉴 이름이 설정한 언어로 나옴
- ☐ **사이드탭**: 단축키(기본 Alt+Shift+S) 또는 `side` 버튼으로 열림. 페이지 가져오기 · 자동 읽기 켜기(모든 사이트 권한 창) · 한 번 누르기 질문 · 전에 물어본 것
- ☐ **이 PC 주소 권한**: 설정 › 로컬 LLM을 켤 때 크롬이 `localhost` 권한을 물음. 거절하면 켜지지 않음
- ☐ 프로젝트 폴더 열기(폴더 접근 허용 창) → 크롬을 껐다 켠 뒤 "다시 연결"
- ☐ 설정 옮기기: 내보내기가 다운로드로 떨어지고, 가져오기가 됨

## 8. 로컬 LLM (실제 Ollama · LM Studio)

- ☐ Ollama(`http://localhost:11434`)를 켜고 설정 › 로컬 LLM › 연결 확인 → 모델 목록이 나옴. 패널에서 질문 → 답이 흘러나옴 · ■로 멈춤
- ☐ LM Studio(`http://localhost:1234`)도 같은 확인
- ☐ 패널 없이 종합 · 토론 판정 · 스킬 압축
- ☐ 컨텍스트 한도를 2k로 낮추고 긴 답으로 종합 → "일부만 보냄" 안내
- ☐ 크롬 확장에서: `OLLAMA_ORIGINS=chrome-extension://*`를 준 Ollama로 같은 확인
- ☐ `localhost`가 아닌 주소(예: `http://192.168.0.2:11434`)는 거절됨

## 9. 설정 옮기기 (앱 ↔ 확장)

- ☐ Windows 앱에서 비밀번호를 넣어 내보낸 `.mla.json`을 크롬 확장에서 가져옴 → 바뀌는 설정 목록이 맞고, 가져온 뒤 설정 · 라이브러리가 같음
- ☐ 반대로 확장 → 앱
- ☐ 틀린 비밀번호는 거절, 언어 설정도 함께 옮겨짐

## 10. 언어 바꾸기 (v0.30.0)

- ☐ 설정 › 언어를 **English**로 → 화면이 그 자리에서 영어로 바뀜 (패널 · 열린 프로젝트 · 쓰던 글은 그대로). 다시 **한국어**로 → 돌아옴
- ☐ 바꾼 뒤 각 화면을 한 번씩: 모델 고르기 · 비교 · 기록 · 설정 · 라이브러리 · 변경 제안 · 프로젝트 사이드바. 옛 언어가 남은 곳을 적어 둠 (패널 상태 글은 다음에 바뀔 때 새 언어가 되는 것이 정상)
- ☐ **자동**: Windows 표시 언어가 한국어인 PC에서는 한국어, 아닌 PC(또는 크롬 언어를 영어로)에서는 영어로 시작
- ☐ 앱을 껐다 켜도 고른 언어로 시작 (첫 화면부터, 한국어가 잠깐 보였다 바뀌지 않음)
- ☐ 크롬 확장: 앱 탭에서 바꾸면 열려 있는 **사이드탭**과 **오른쪽 클릭 메뉴**도 따라 바뀜
- ☐ 본체가 띄우는 창(파일 저장 · 테스트 실행 확인)과 OS 알림도 고른 언어
- ☐ 영어 화면에서 종합 · 분석 · 토론을 해 봄 (v0.31.0부터 요청 글도 영어). 실제 AI가 영어 머리글(`## Common ground` …)대로 답해 **분석 표가 깨지지 않는지**, 프로젝트 모드의 영어 답변 규칙(`File: path` · `<<<<<<< SEARCH`)대로 수정안을 읽는지
- ☐ 영어 ↔ 한국어를 오가며 기본 템플릿(요약 · 번역 · 코드 리뷰)이 바뀐 언어로 나가는지

## 11. 키보드만으로 한 바퀴 (접근성)

마우스를 쓰지 않고 해 봅니다. 자세한 기준은 [접근성](accessibility.md).

- ☐ Tab으로 툴바 → 입력창 → 보낼 대상 → 종합까지 닿고, **지금 어디에 있는지 파란 테두리로 보임**
- ☐ `Ctrl+L`로 입력창, 질문 쓰고 Enter로 보내기, `Ctrl+Shift+D`(비교) · `Ctrl+H`(기록) · `Ctrl+/`(설정) 단축키로 화면 오가기 (설정 › 단축키 표)
- ☐ 창(보내기 전 미리보기 · 토론 · 미리보기/적용 · 화면 상태 · 설정 가져오기): 열리면 포커스가 안으로 들어가고, Tab이 창 밖으로 새지 않고, **Esc로 닫히며**, 닫힌 뒤 열기 전 버튼으로 돌아옴
- ☐ 기록 목록 · 라이브러리 목록 · 프리셋 목록의 줄을 Tab + Enter로 고름. 프로젝트 파일 나무에서 폴더 펼치기 · 파일 열기
- ☐ 분석 표의 칸을 Tab + Enter로 눌러 그 답변으로 이동
- ☐ 사이드탭: 모델 고르기 · 페이지 가져오기 · 한 번 누르기 질문 · 보내기
- ☐ (할 수 있으면) NVDA 또는 Windows 내레이터로: 기호 버튼(`?` `→` `⤢` `↻`)이 이름으로 읽히고, 창 제목과 "답변 완료 3/4" 같은 안내가 읽힘

## 11-2. 첫 사용 안내 · 확대 · 파일 나무 (v0.31.0)

- ☐ 깨끗한 프로필(`MLA_PROFILE`를 새 폴더로)로 앱을 켜 패널 화면에 들어가면 **처음 사용 안내**가 한 번 뜸. `건너뛰기`로 닫고 앱을 껐다 켜면 다시 안 뜸. 설정(`?`) › **다시 보기**로는 다시 뜸. 예전 프로필(v0.30.0에서 쓰던)에서는 안 뜸
- ☐ 크롬 확장도 같은 확인 (확장 저장소를 지운 새 크롬 프로필)
- ☐ **확대**: `Ctrl` `+` `-` `0`이 앱 화면만 키우고, AI 사이트 패널은 그대로이며, **패널이 툴바 · 입력창과 겹치거나 틈이 벌어지지 않음**(grid · row · main · 2col 모두, 프로젝트 사이드바를 연 채로도). 창 크기를 바꿔도 맞고, 앱을 껐다 켜도 같은 배율. 숫자판 `+` `-` `0`도
- ☐ **파일 나무**: 프로젝트를 열고 Tab으로 나무에 들어가 `↑` `↓` `→` `←` `Home` `End` `Enter` `Space`가 설명대로 동작하고, 펼치거나 체크해도 포커스가 그 줄에 남음. 화면 읽기 프로그램이 "트리 항목, 수준 2, 펼쳐짐" 같이 읽는지 (NVDA · 내레이터)
- ☐ 버튼 · 입력칸 테두리가 어두운 화면에서 눈에 잘 들어오는지 (옅은 선 · 진한 선이 섞여 어색한 곳이 없는지)
- ☐ 나눈 파일이 실제로 돌아가는지: 변경 제안 › 큰 작업(파일별로 받기) · 이어서 받기 · 테스트 실행 · 파일 모아보기, 크롬 확장에서 패널 열기 · 원격 셀렉터 확인 · 업데이트 확인

## 11-3. 답 다루기 (v0.32.0)

- ☐ 실제 AI 4개로 분석 요청 → 머리줄 **합의율**과 이견 줄의 `n/N 같음`이 눈으로 봐도 말이 되는지 (같은 말을 다르게 쓴 입장이 따로 세어지거나 다른 말이 합쳐지지 않는지 — 어림값이므로 크게 어긋나는 경우를 릴리스 노트에 적음). 답변에 링크가 있으면 **출처** 칸에 모이고 **복사**가 되는지
- ☐ **토론 역할**: 찬성 · 반대 · 반론 전담을 주고 2라운드 → 실제 AI가 그 쪽에서 답하는지, 판정이 역할에 끌려가지 않는지
- ☐ **끼어들기**: 켜고 시작 → 1라운드 뒤 창이 뜸 → 한마디를 넣으면 2라운드 요청에 붙고 3라운드에는 안 붙음. `Esc`로 닫은 뒤 **끼어들기** 단추로 다시 열림. 패널 화면(Windows 앱)에서 창이 패널에 가려지지 않음. 토론 멈추기 · 앱을 다른 화면으로 옮겨도 이상하지 않음
- ☐ 역할 · 끼어들기를 켠 채 **프리셋 저장** → 다른 프리셋을 고른 뒤 다시 고르면 토론 창이 같은 값으로 열림
- ☐ **보기 방식** 네 가지를 실제 답변으로: 문단 맞추기가 말이 되게 짝짓는지(엉뚱한 짝이 많으면 기록), 코드만, 표 비교(표로 답하는 질문으로). 고른 방식이 껐다 켜도 기억되는지. 크롬 확장에서도 같은지

## 11-4. 작업 흐름 · 사실 확인 (v0.33.0)

- ☐ **다른 언어 검사**: Python(`pyproject.toml`) · Rust(`Cargo.toml`) · Go(`go.mod`) 프로젝트를 열고 미리보기 창에 `pytest` · `cargo-test` · `go-test` 칸이 나오는지(해당 파일이 없으면 안 나옴), 실제로 실행되고 통과 · 실패 수가 맞는지. 실행 파일이 PATH에 없으면 "찾지 못함" 안내가 나오는지. - ☐ **창 ↔ 카드**: 로드맵 창에서 상태를 바꾸면 카드가, 카드에서 바꾸면 창이 바로 따라가는지. `전체 보기 ↗`가 그 작업을 보여 주는지
- ☐ **크롬 확장**: 같은 카드가 앱 탭에 보이고, 적용 뒤에는 테스트 실행 없이 **완료 · 막힘**만 보이는지
- ☐ **영어 화면**: 카드 글이 영어로, 좁은 창(960px)에서 버튼이 넘치지 않는지

- ☐ **없는 도구 · 버전**: `engines.node`를 지금 버전보다 높게 바꾸면 노랑 `버전 안 맞음`, 없는 도구(예: Go)는 빨강 · 설치 명령 복사 · 설치 안내 ↗가 기본 브라우저로 열리는지
- ☐ **PATH에 없음**: PATH에서 한 폴더(예: MSYS2 `ucrt64\bin`)를 빼고 앱을 다시 켜면 `PATH에 없음`과 그 폴더가 보이는지
- ☐ **준비 상태**: `node_modules`를 지우면 `npm install` 줄, `.env.example`만 두면 `.env` 줄, 5173 포트를 다른 프로그램이 쓰면 포트 줄, Docker Desktop을 끄면 엔진 줄
- ☐ **프로젝트 안 실행 파일**: 프로젝트 폴더 안에 가짜 `node.exe`를 두고 PATH에 그 폴더를 넣어도 쓰지 않는지
- ☐ **고치기**: 자세히 창에서 도구를 빼고 더한 것이 앱을 다시 켜도 남는지
- ☐ **크롬 확장**: 같은 칸이 파란색 "필요한 도구 N"과 안내 글만 보이는지
- ☐ **영어 화면 · 좁은 창(960px)**: 칸 글 · 표가 넘치지 않는지

## 11-10. 크롬 확장 로그인 · 동의 안내 (v0.38.2)

- ☐ **자동 다시 연결**: 로그아웃 상태 패널(예: 시크릿 아닌 새 프로필의 Gemini) → `로그인 필요` + **로그인 탭** → 새 탭에서 로그인 → 앱 탭으로 돌아오면 몇 초 안에 패널이 저절로 다시 열리고 로그인된 화면인지. 사이드탭에서도 같은지(사이드 패널은 열어 둔 채 탭에서 로그인)
- ☐ **되풀이 없음**: 로그인 탭을 누르고 로그인하지 않은 채 1~2분 두었을 때 패널이 계속 깜빡이며 다시 열리지 않는지(최소 10초 간격), 로그인 탭을 누르지 않은 패널은 쿠키가 바뀌어도 그대로인지
- ☐ **보내기 실패 안내**: 로그아웃 패널에 질문을 보내면 `로그인 필요 — …` 오류와 로그인 탭 버튼이 뜨는지(다른 패널은 정상으로 보내짐)
- ☐ **Duck.ai 동의**: 동의 화면이 뜨는 환경(새 프로필 · 영어 지역)에서 `처음 사용 — 패널 안의 동의 버튼을 눌러 주세요`가 뜨고, 확장이 버튼을 누르지 않는지, 직접 누르면 몇 초 안에 안내가 사라지는지. 동의 화면이 없는 환경에서는 안내가 뜨지 않는지
- ☐ **스토어 심사 안내**: `store/README.md` 3절의 A · B · C 순서를 영어 화면에서 그대로 따라 해 보고, 적힌 버튼 이름 · 안내 글이 화면과 같은지
